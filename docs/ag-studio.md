# The desk on AG Studio

Back to the [README](../README.md).

The hosted desk is an [AG Studio](https://www.ag-grid.com) report (`studio/`), not a page with a chart library bolted on. What it uses, and where:

- **Custom widgets.** 19 JUNCO widget types registered with `createWidgets` (`studio/src/widgets/definitions.ts`): Waiting for you, Agent activity, Start here, the Gate record, the dispute queue, the case card, Dispute this store, the Incident page, the Books, Who else?, Break the mandate, the Escape room, Try it, the Policy page, shipment watch, summary stats, at risk this week, simulated lifecycle outcomes and Matching disputes. Each reads the desk's own API; Studio owns layout, theming and the pages.
- **Studio's data engine.** The Insights page runs on a Studio data source built from the live PayPal cases (`studio/src/insights.ts`): two button filters, a donut, a column chart and a bar chart of the amount by what JUNCO says, all native Studio widgets. Matching disputes is a JUNCO widget that reads its rows through the same engine (`widgetApi.getSchema` and `widgetApi.getData`), so a filter or a click on a chart narrows the list the way it narrows the charts.
- **Theme.** `studioTheme.withParams` in `studio/src/App.tsx` gives Studio's native widgets the desk's palette, type, borders and corners, in light and dark.
- **The AI assistant, through JUNCO's gate.** `AgStudioAiModule` with `createAiHarness` and `directLlmRunner` (`studio/src/studioAi.ts`). The model behind it is a custom `AgLlmAdapter` that streams each turn from `/api/studio-ai` on the desk (`src/studio-ai.ts`, Claude Sonnet 5.5 with prompt caching), with turn limits per agent. JUNCO is its own agent (`id: 'junco'`, where every chat starts): it keeps the built-in lead's instructions and Studio tools and has its own `delegateTo` to Studio's built-in data, page, widget and planning agents. Asked for a chart of the disputes it's about to lose, it hands the query to the data agent, the placement to the page agent and the chart to the widget agent, and the trace shows each hand-off (3 of 3 runs on Oct 16, `npm run check-studio-ai 3`). JUNCO gets five tools of its own (explain a case, policy what-if, open a case, the activity log, the shipment watch) and the same gated PayPal tools every other agent gets: a money move it asks for lands in Waiting for you, tagged "asked by the dashboard assistant". Tool Components (the `aiToolDisplay` prop) label every tool call so the trace reads as work, and a gated PayPal write shows as a gate card (`studio/src/widgets/GateCard.tsx`) whose Approve and Reject go through the same hold path as the Desk; three prompt starters open the panel.
- **Edit mode.** With the assistant on, the Desk is in Studio's edit mode: an owner can resize any panel from its edge, and `onStateUpdated` saves the sizes in that browser (Policy page: Reset the layout). Visitors don't get Studio's widget toolbar. Below 900 px the Desk is in view mode with every panel stacked full width, so the assistant panel never covers the queue on a phone.
- **AG Grid.** The dispute queue is an AG Grid Community grid (`studio/src/widgets/QueueWidget.tsx`). Who else? is another (`studio/src/widgets/WhoElseWidget.tsx`): groups that open and close, a money total on each group's row, sorting inside a group (`postSortRows`), an editable Keep column the owner plans from, a pinned total of what's kept that moves as rows are dropped, and rows that open in place for their records. Row grouping and detail rows are Enterprise modules, so the groups are built in `studio/src/ui.ts` and a row's detail is a full-width row on Community features, which need no licence question.
